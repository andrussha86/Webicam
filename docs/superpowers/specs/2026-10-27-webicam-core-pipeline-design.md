# Webicam — подпроект 1: базовый видеоканал iPhone → Windows

Дата: 2026-10-27
Статус: дизайн утверждён, ожидает ревью спецификации

## 1. Цель и контекст

**Webicam** — открытый аналог Camo Studio: iPhone, подключённый по USB, становится
веб-камерой с низкой задержкой в Windows 11 и виден всем приложениям (Zoom, Teams,
Discord, OBS, браузеры, «Камера»). Проект для личного использования автора и для всех,
кто возьмёт его с GitHub (самостоятельная установка, без App Store и без подписанных драйверов).

### Дорожная карта (каждый подпроект — отдельная спецификация и план)

1. **Базовый видеоканал (этот документ)** — захват и кодирование на iPhone, передача по USB,
   декодирование на ПК, виртуальная камера Windows 11, выбор разрешения/FPS захвата.
2. **Управление камерой** — ISO, выдержка, баланс белого, фокус, экспокоррекция,
   выбор объектива (0.5×/1×/2×/3×) и зум, форматы обрезки (16:9, 4:3, 1:1, 9:16).
3. **Автослежение** — детекция и трекинг главного объекта, плавный цифровой кроп
   из кадра высокого разрешения (аналог Center Stage).
4. **Фон** — сегментация главного объекта (Vision, Neural Engine) и композитинг со своим
   фоном (картинка, видео, размытие).
5. **Микрофон** — отложен: виртуальный аудиовход в Windows требует драйвера режима ядра.

### Вне рамок подпроекта 1

Ручные настройки камеры, объективы, кроп, трекинг, фон, звук, Android, macOS,
Windows 10, подключение по Wi-Fi.

## 2. Платформы и ограничения

| | |
|---|---|
| Телефон | iPhone, минимальная версия **iOS 17**. Эталонное устройство: iPhone 15 Pro (iOS 27). |
| ПК | **Только Windows 11** (нужен `MFCreateVirtualCamera`, Windows 11 build 22000+). |
| USB-транспорт | Служба Apple Mobile Device Support (приложение «Apple Devices» из Microsoft Store или iTunes), usbmux на `127.0.0.1:27015`. |
| Сборка iOS | Mac нет. Сборка в **GitHub Actions** (macOS-раннер), установка через **Sideloadly** с Apple ID пользователя. |
| Сборка Windows | Локально: Visual Studio 2022 / Build Tools + CMake; дополнительно в CI. |
| Кодек | **H.264**. HEVC не используется: декодер HEVC не всегда установлен в Windows 11 по умолчанию. |

Следствия:
- iOS-приложение должно быть открыто на переднем плане, пока идёт трансляция:
  iOS останавливает камеру в фоне.
- Подпись бесплатным Apple ID действует 7 дней, потом нужна переустановка
  (Sideloadly умеет обновлять автоматически).
- Отладчика для iOS нет, iOS-часть отлаживается по логам. Поэтому iOS-часть держим тонкой,
  а Windows-часть должна разрабатываться без телефона (см. §8, `fake-phone`).

## 3. Архитектура

Выбран вариант «толстое приложение, тонкая камера»: соединение, декодирование, превью
и управление живут в обычном процессе `webicam.exe`. DLL виртуальной камеры, которая
загружается в системную службу Frame Server, только читает готовые кадры из общей памяти.

```
iPhone                                Windows 11
┌────────────────────────┐            ┌──────────────────────────────────────┐
│ CaptureEngine          │            │ webicam.exe                          │
│   ↓ CVPixelBuffer      │            │  UsbmuxClient → DeviceSession        │
│ Encoder (H.264, VT)    │   USB /    │    ↓ H.264                           │
│   ↓ Annex B            │   usbmux   │  Decoder (MF, D3D11, low latency)    │
│ StreamServer :47800 ───┼───────────▶│    ↓ NV12 (GPU)                      │
│ ControlHandler ◀───────┼────────────┤  Scaler (D3D11 Video Processor)      │
│ StatusView             │            │    ├→ превью (ImGui)                 │
└────────────────────────┘            │    └→ FramePublisher                 │
                                      │        ↓ общая память (3 слота)      │
                                      │  VirtualCamHost (MFCreateVirtualCamera)
                                      └───────────────┬──────────────────────┘
                                                      ↓
                                      ┌──────────────────────────────────────┐
                                      │ webicam_vcam.dll (в Frame Server)    │
                                      │  IMFMediaSource → Zoom / OBS / ...   │
                                      └──────────────────────────────────────┘
```

Управление выполняется **из приложения на ПК**. Телефон показывает только статус и кнопку «Стоп».

## 4. Компоненты

### 4.1 iOS-приложение (Swift, SwiftUI)

| Компонент | Ответственность |
|---|---|
| `CaptureEngine` | `AVCaptureSession`, основная широкоугольная камера, выбор `AVCaptureDevice.Format` по разрешению и FPS, выдача `CVPixelBuffer` с временем захвата. |
| `Encoder` | `VTCompressionSession`, H.264 Annex B; `RealTime = true`, low-latency rate control (`kVTVideoEncoderSpecification_EnableLowLatencyRateControl`), без B-кадров (`AllowFrameReordering = false`), ключевой кадр раз в 2 с и по запросу. Если кодер занят, кадр отбрасывается, очереди нет. |
| `StreamServer` | `NWListener` на TCP-порту **47800**, привязка **только к loopback**. Один клиент одновременно: новый вытесняет старого. |
| `ControlHandler` | Обработка `Configure` и `RequestKeyframe`, ответы на `Ping`, отправка `Status`. Реакция на `thermalState`. |
| `StatusView` | «Ожидание ПК» / «Подключено», текущие разрешение, FPS и битрейт, кнопка «Стоп», затемнение экрана, `isIdleTimerDisabled = true`. |
| `WebicamCore` (Swift Package) | Кодирование и разбор протокола, таблица битрейтов по умолчанию. Без зависимостей от камеры; тестируется `swift test`. |

### 4.2 `webicam.exe` (C++20, CMake, Dear ImGui на D3D11)

| Компонент | Ответственность |
|---|---|
| `UsbmuxClient` | Соединение с `127.0.0.1:27015`, протокол usbmux (plist-сообщения `Listen`, `ListDevices`, `Connect`), события подключения и отключения, открытие туннеля к порту 47800 устройства. |
| `DeviceSession` | Протокол Webicam поверх сокета (§5): рукопожатие, приём кадров, отправка команд, синхронизация часов, переподключение. |
| `Decoder` | Media Foundation H.264 decoder MFT с D3D11 (DXVA) и `CODECAPI_AVLowLatencyMode = TRUE`; выход — NV12-текстура. При ошибке ждёт ключевого кадра. |
| `Scaler` | D3D11 Video Processor: масштабирование в формат, выбранный потребителем, с сохранением пропорций (letterbox/crop по центру). |
| `FramePublisher` | Копия кадра в CPU и запись в кольцевой буфер общей памяти (§6), heartbeat. |
| `VirtualCamHost` | `MFCreateVirtualCamera` (тип Software, lifetime **Session**, имя «Webicam»), `Start` при запуске, удаление при выходе. |
| `UI` | Список устройств, превью, выбор разрешения и FPS захвата, битрейт, статистика: FPS, задержка до общей памяти, потерянные кадры, состояние соединения. Сворачивание в трей. |
| `--direct host:port` | Отладочный режим: подключение напрямую по TCP, минуя usbmux (для `fake-phone`). |

### 4.3 `webicam_vcam.dll` (C++20, COM, Media Foundation)

- Реализует `IMFMediaSource` / `IMFMediaStream` с одним видеопотоком NV12. Регистрируется
  как COM in-proc server с фиксированным CLSID.
- Объявляет список форматов: 640×360, 1280×720, 1920×1080, 3840×2160 при 30 и 60 FPS
  (4K — только 30).
- Записывает выбранный потребителем формат в управляющий блок общей памяти.
- На каждый запрос сэмпла берёт **самый свежий** опубликованный кадр. Если формат кадра
  ещё не совпадает с запрошенным (во время переключения), отдаёт заглушку нужного размера.
- Если heartbeat от `.exe` не обновлялся дольше 1 с или телефон отключён, показывает последний
  кадр затемнённым с надписью «Нет сигнала». Если кадра ещё не было — заглушку
  «Webicam: телефон не подключён».

### 4.4 `shared/`

- `protocol.md` — нормативное описание протокола (источник истины для обеих сторон).
- `testvectors/` — бинарные образцы каждого сообщения; ими проверяются и C++, и Swift.
- C++-заголовки протокола и раскладки общей памяти используют и `.exe`, и `.dll`.

## 5. Протокол

Транспорт — TCP через usbmux-туннель. Все целые числа little-endian.

Кадр сообщения: `type: u8 | length: u32 | payload[length]`. Максимальный `length` — 16 МиБ;
превышение считается ошибкой протокола и закрывает соединение.

| Тип | Код | Направление | Payload |
|---|---|---|---|
| `Hello` | 0x01 | оба, первым сообщением | `protocol_version: u16`; от телефона дополнительно `model: str`, `formats: [{width: u16, height: u16, max_fps: u8}]` |
| `Configure` | 0x02 | ПК → тел | `width: u16, height: u16, fps: u8, bitrate_kbps: u32` |
| `VideoFrame` | 0x03 | тел → ПК | `capture_time_us: u64` (монотонные часы телефона), `flags: u8` (бит 0 — ключевой кадр), далее H.264 Annex B; ключевой кадр содержит SPS/PPS |
| `RequestKeyframe` | 0x04 | ПК → тел | пусто |
| `Ping` | 0x05 | ПК → тел | `pc_time_us: u64` |
| `Pong` | 0x06 | тел → ПК | `pc_time_us: u64, phone_time_us: u64` |
| `Status` | 0x07 | тел → ПК | `state: u8` (streaming / stopped_by_user / thermal_throttled / error), `thermal: u8`, `message: str` |

`str` = `length: u16` + UTF-8. Массив = `count: u16` + элементы.

Правила:
- Обе стороны первым делом шлют `Hello`. Если `protocol_version` не совпадает, соединение
  закрывается, UI показывает, какую сторону обновить.
- Трансляция начинается только после `Configure`. Новый `Configure` перенастраивает захват
  и кодер, первый кадр после него — ключевой.
- ПК шлёт `Ping` раз в секунду. Смещение часов оценивается по минимальному RTT за окно
  из 10 замеров. Задержка кадра = время ПК при публикации − (`capture_time_us` + смещение).

### Битрейт по умолчанию

| Захват | Битрейт |
|---|---|
| 720p30 / 720p60 | 8 / 12 Мбит/с |
| 1080p30 / 1080p60 | 16 / 25 Мбит/с |
| 4K30 | 45 Мбит/с |

Битрейт можно переопределить в UI.

## 6. Общая память

Именованная секция `Global\WebicamFrames-v1`: Frame Server работает в сессии 0, а
`webicam.exe` — в сессии пользователя, поэтому нужно глобальное пространство имён.
Создавать объекты в `Global\` может только процесс с `SeCreateGlobalPrivilege`. У Frame Server
она есть, у обычного пользователя — нет. Поэтому:

- секцию **создаёт DLL** при первой активации источника, с DACL, который разрешает
  чтение и запись `LOCAL SERVICE` и интерактивным пользователям (`INTERACTIVE`);
- `webicam.exe` **открывает** существующую секцию. Пока её нет (ни один потребитель ещё
  не открыл камеру), `.exe` работает только на превью и повторяет попытку открытия раз в 500 мс.

**Риск, который нужно проверить первым в плане:** создание `Global\`-секции из DLL внутри
Frame Server и её открытие из `.exe`. Запасной вариант — канал от `.exe` к источнику через
`IMFVirtualCamera::AddProperty`/custom-интерфейс или именованный пайп.

Раскладка:
- **Управляющий блок:** версия раскладки, `heartbeat_ms: u64` (пишет `.exe`),
  `connected: u32` (пишет `.exe`), `requested_width/height/fps` (пишет DLL),
  `latest_slot: u32` с номером поколения (пишет `.exe`, атомарно),
  `reading_slot: u32` (пишет DLL).
- **3 слота кадров**, каждый на максимальный NV12 4K (3840×2160×1.5 байт ≈ 12 МиБ):
  `width, height, stride, timestamp_100ns, generation` + данные.

Протокол без блокировок: писатель выбирает слот, отличный от последнего опубликованного
и от того, который читатель пометил как читаемый (`reading_slot`), пишет кадр и атомарно
публикует номер слота с увеличенным поколением. Читатель копирует слот и перепроверяет
поколение; если оно изменилось, повторяет. Старые кадры никогда не ставятся в очередь.

## 7. Жизненный цикл и ошибки

| Ситуация | Поведение |
|---|---|
| Служба Apple Mobile Device недоступна | UI: «Установите Apple Devices из Microsoft Store», повтор каждые 2 с. |
| iPhone не доверяет ПК | UI: «Разблокируйте iPhone и нажмите „Доверять“». |
| Приложение на iPhone не открыто | UI: «Откройте Webicam на iPhone», попытки соединения каждые 1–2 с. |
| Несколько iPhone | Выбор в UI; если айфон один, подключение автоматическое. |
| Обрыв (кабель, блокировка, сворачивание) | DLL показывает «Нет сигнала», камера в потребителе не пропадает. `.exe` переподключается сам и запрашивает ключевой кадр. |
| Ошибка декодирования | Кадры отбрасываются до ключевого, отправляется `RequestKeyframe`. |
| `thermalState = serious` | Телефон снижает FPS до 30 и битрейт на 30 %, шлёт `Status`; UI показывает предупреждение. |
| `thermalState = critical` / iOS остановила камеру | `Status(error)` с причиной; UI показывает её. |
| Пользователь нажал «Стоп» на телефоне | `Status(stopped_by_user)`, DLL — «Нет сигнала». |
| `.exe` упал | Heartbeat устаревает, DLL показывает «Нет сигнала». Frame Server продолжает работать. |
| `.exe` закрыт | Камера (lifetime Session) удаляется из системы. Сворачивание в трей её сохраняет. |
| Ошибка протокола / несовпадение версии | Соединение закрывается, UI показывает причину. |

Безопасность: порт 47800 на телефоне слушает только loopback, по сети он недоступен;
доступ к общей памяти ограничен DACL; DLL проверяет размеры и смещения из общей памяти
перед чтением.

## 8. Структура репозитория и сборка

```
/ios
  project.yml          XcodeGen (сгенерированный .xcodeproj не хранится в git)
  /WebicamCore         Swift Package: протокол
  /WebicamApp          приложение
/windows
  CMakeLists.txt, vcpkg.json (Dear ImGui, GoogleTest)
  /core                usbmux, протокол, декодер, скейлер, общая память (static lib)
  /app                 webicam.exe
  /vcam                webicam_vcam.dll
  /tools/fake-phone    отправка тестового H.264 по протоколу Webicam через TCP
  /tests
  install.ps1          регистрация DLL (требует администратора), uninstall.ps1
/shared
  protocol.md
  /testvectors
/docs
```

- **CI iOS** (GitHub Actions, `macos-latest`): `brew install xcodegen` → `xcodegen` →
  `swift test` для `WebicamCore` → `xcodebuild archive CODE_SIGNING_ALLOWED=NO` →
  упаковка `Payload/Webicam.app` в `Webicam.ipa` → артефакт.
- **CI Windows** (`windows-latest`): CMake + MSVC + vcpkg, сборка, запуск тестов, zip с
  `webicam.exe`, `webicam_vcam.dll`, `install.ps1`.
- **Релиз**: push тега `v*` → GitHub Release с `.ipa` и zip.
- Сертификаты и ключи подписи в репозитории не хранятся.

## 9. Тестирование

- **Совместимость протокола:** тест-векторы из `/shared/testvectors` разбираются и
  генерируются одинаково в C++ (GoogleTest) и Swift (`swift test`).
- **C++ unit-тесты:**
  - кольцевой буфер, включая стресс-тест «писатель и читатель в разных потоках»;
  - разбор протокола, включая обрезанные и слишком длинные сообщения;
  - `UsbmuxClient` против фейкового usbmuxd (локальный TCP-сервер);
  - `Decoder` на тестовом H.264-клипе из репозитория;
  - оценка смещения часов.
- **Интеграция без телефона:** `fake-phone` + `webicam.exe --direct 127.0.0.1:47800` →
  виртуальная камера видна в OBS и приложении «Камера».
- **Ручной чек-лист на устройстве:** первое подключение и доверие, переподключение
  после выдёргивания кабеля, блокировка телефона, смена разрешения и FPS, два потребителя
  одновременно (OBS + браузер), длительная работа 30 минут (нагрев).
- **Задержка:** на мониторе миллисекундный таймер, iPhone снимает его, вывод камеры в OBS
  на том же мониторе; разница на скриншоте = задержка от объектива до экрана.

## 10. Критерии готовности

1. После `install.ps1` в Windows 11 появляется камера «Webicam». Её видят Zoom, OBS,
   браузер (Chrome/Edge) и приложение «Камера».
2. 1080p60 работает стабильно 30 минут; задержка от объектива до экрана **меньше 100 мс**.
3. Выдёргивание и подключение кабеля восстанавливает картинку без повторного выбора
   камеры в потребителе.
4. Разрешение и FPS захвата переключаются из приложения на ПК без перезапуска потребителя.
5. CI собирает `.ipa` и Windows-zip; `.ipa` ставится через Sideloadly и работает.
